# Design C — Dense Rack

## Назначение

Design C — интерфейс локальной инженерной консоли NanoPi R5S. Он должен ощущаться как операторская панель: высокая плотность полезных данных, строгая геометрия, однозначные статусы и минимум декоративного шума.

## Визуальная система

- Шрифт: локальный variable font `Geist Mono`, fallback — системный monospace.
- Фон: `#07090b`; панели: `#090d11`; поднятые элементы: `#0c1216`.
- Основной текст: `#c9e3e9`; вторичный: `#6d8790`; разделители: `#1c3038`.
- Акцент и фокус: `#43d9ff`; успех: `#75f0a5`; предупреждение: `#dfbd5c`; ошибка: `#ff667a`.
- Геометрия прямоугольная: без карточек-капсул, декоративных скруглений и градиентов.
- Верхняя панель — 48 px, desktop sidebar — 218 px. Основной шаг отступов — 4 px; рабочие значения 8, 12, 16 и 24 px.
- Заголовки компактные. Технические подписи набираются uppercase с увеличенным tracking.

## Компоновка

- Постоянный верхний статус-бар показывает идентичность сессии и активный линк.
- Sidebar содержит node tree, навигацию и быстрые метрики.
- Обзор начинается со status strip, затем показывает живые метрики узла, service matrix, интерфейсы и security boundary.
- Маршрутизатор разделён на конфигурацию и sticky change-control. Применение остаётся одной операцией с автоматическим подтверждением связи и 120-секундным автооткатом.
- Firewall, Docker и диагностика используют таблицы/матрицы вместо свободных карточек.
- На экранах до 760 px sidebar превращается в нижнюю навигацию; таблицы складываются в компактные строки.

## Правила поведения

- Показывать реальные данные API. Не генерировать фиктивные метрики, события или состояния.
- Цвет всегда дублировать текстовой меткой (`ONLINE`, `FAULT`, `PENDING`).
- Опасные операции отделять от основных и требовать подтверждение там, где оно уже предусмотрено продуктом.
- Технические ошибки показывать в раскрываемом блоке; краткое состояние оставлять читаемым.
- Сохранять текущую модель безопасности: web-процесс без root, привилегированные операции через локальный agent.

## Промпт для ИИ

> Развивай NanoPi Manager в стиле Design C / Dense Rack. Используй текущие страницы, DOM-события и API-контракты как функциональную основу. Создавай строгую тёмную инженерную консоль с высокой информационной плотностью, прямоугольной геометрией и локальным Geist Mono. Палитра: фон #07090b, панели #090d11, raised #0c1216, линии #1c3038, текст #c9e3e9, muted #6d8790, cyan #43d9ff, green #75f0a5, amber #dfbd5c, red #ff667a. Не используй градиенты, декоративные скругления, большие hero-блоки, маркетинговые иллюстрации или вымышленные данные. Отдавай приоритет таблицам, status strip, service matrix, node tree, topology и change-control. Все состояния подписывай текстом, обеспечивай keyboard focus и адаптацию под мобильный экран. Не меняй однокнопочный сценарий router apply: валидация, атомарная запись, автоматическая проверка нового адреса и автооткат через 120 секунд должны остаться целостной операцией.
